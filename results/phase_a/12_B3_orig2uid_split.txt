B3: decompose orig2uid into (zero-flags, non-zero values)

Why, in one measurement. orig2uid on E. coli:
  entries 1,553,259   raw 6,213,036 B (32 bits/read)
  value 0 appears 1,235,646 times = 79.55%   (reads that are not duplicates)
  non-zero entries      317,613 = 20.45%     (sparse alias payloads)
  distinct values       273,172
  order-0 entropy over values 4.408 bits -> floor 855,909 B

One stream carrying two unrelated signals: a dense boolean (is this read a
duplicate?) and a sparse integer payload. No single model fits both, which is
why this stream needed the 7-way probe and became the coding pool's floor at
4.53 s -- longer than `literal`, which is BIGGER (7.76 MB) but homogeneous and
takes 0.38 s through the DNA coder.

PgRC2 splits this shape rather than searching for a coder that copes. Their own
log:
  Mismatches counts (zero flags)      fse_coder    1533585 -> 144336
  Mismatches counts (non-zero values) range_coder   331318 -> 191194
We already did it for mm_cnt and had not done it for orig2uid.

E. coli after the split:
  orig2uid 6,213,036 B -> flags 194,158 B + vals 1,270,452 B
  job 4.53 s -> 0.83 s + 0.18 s
  pool wall 4.50 s -> 2.65 s, floor moves off orig2uid to pos_abs
  archive 7,965,384 -> 7,888,867 (-76,517 B)

7 files: size 79,869,125 -> 79,693,000 (-176,125 B, -0.22%), wall -8.6%.
  ecoli -76,517   saureus -73,826   pfalc -25,814
  paeru/halo/sulfo/lmajor +8 each -- one extra stream-table entry on files whose
  orig2uid is entirely zeros (no duplicate reads), so the split carries nothing.
Lossless verified on H. salinarum, E. coli, S. aureus.

Note what this says about the probe. The probe was not a tuning knob to shrink;
it was compensating for heterogeneity one layer up. Removing the heterogeneity
made the stream 4.2x smaller AND the archive smaller -- handing the coder the
structure beats making it discover the structure.
